# Learning Lens 接入草案

2026-10-19。本文保留最初的讨论方案。通用 LoopPolicy、JS Lens 加载及 TUI/A2A 接入已经实现；当前可用契约见 [smallhead-lens](../crates/smallhead-lens/README.md)。包清单实际采用 `lens.json`，不是下文早期建议的 `lens.toml`。

后续实现已补齐领域工具注册：完整学习包通过通用 extension 接口向 TUI/A2A 提供八项 Rust 学习工具、领域提示词和循环策略；包加载、卸载影响下一任务，数据库保留。契约见 [Lens 领域工具扩展](lens-domain-extensions.md)。本仓库 `lenses/learning` 仍是纯策略演示；完整包在 Learning Agent 项目。引用专用 TUI 展示、A2A 候选审阅仍未实现。下文的现状表及候选流程是设计时基线，不代表最新运行状态。

方向补充：Lens 应是通用可开发、装卸的扩展包，Learning 只是首个领域实例。通用机制见 [Lens 插件运行机制草案](lens-plugin-runtime-proposal.md)。下文学习适配依照通用接口落地，不作为 TUI 专用硬编码。

运行策略补充：Lens 可以用代码改变 system、逐波次模型请求、工具语义与调用处理、验证和继续/结束规则。学习资料工具只是其一部分；首版需包含真正的 loop 策略接口，不能只做声明式提示词与工具安装。

## 目标与使用体验

用户在 Smallhead 中说“今天继续看 Trask 第四章”，沿用正常聊天、补充信息、计划与方案审阅；按需取得课程位置、教材、核对后的引文和学习记忆。

用户可以直接编写 Lens 文件，也可让另一 agent 通过 A2A 提交一个候选。用户明确要求的修改可以沿用该授权完成；其他 agent 主动提交的候选先展示具体差异，由用户决定是否采用。接收、保存候选和启用必须分别回执。

首个候选例子：“用户不理解名词时，先从可观察的现象、预测或尝试出发，再说明关系及名称；不要每轮强制完整教学流程。”

目标不是再做一个固定 Planner → Teacher 工作流。模型在 ReAct 中自主选择行动；Lens 的代码策略可按任务和证据调整环节及继续/结束判断，模型调用、工具执行和协议管理复用 Smallhead 的执行底座。

## 当前实现与缺口

| 部分 | 已有能力 | 缺口 |
| --- | --- | --- |
| 学习宿主 | 直接构造 Smallhead AgentLoop，注册六个 ExternalTool，保存原生消息 | 是独立 CLI，不是在 Smallhead TUI 中可选的学习能力 |
| 学习领域 | learning_context、select_unit、search_materials、read_passage、cite_passage、learning_memory | 尚无供多个宿主直接复用的公共 library 入口 |
| 每轮绑定 | begin_turn 绑定真实输入；记忆保存检查本轮逐字证据 | TUI steering、委派和 A2A 的输入来源还需显式对接 |
| 引用展示 | cite_passage 核对片段；宿主在回答后打印 verified_quotes | TUI 需要结构化结果或展示事件，不能照搬 stdout 打印 |
| Smallhead 工具 | ExternalTool 可注册宿主工具；MCP 可接外部工具进程 | 尚无 Lens 文件发现、校验、版本和启用入口 |
| Monad | 可并行研究、报告、暂停、转交信息、恢复 | 当前默认子角色不包含学习工具，也没有 Lens 配置参数 |
| A2A | 本地消息、任务回执、会话留存 | driver 只注册 monad_bridge；拒绝 mutate/execute/forward，没有 Lens 提案与 TUI 待办 |

Smallhead 的 smallhead-skill 当前仍是占位模块。不能把已有 ExternalTool、Monad 或 MCP 连接能力描述成 Lens 热加载已完成。

## Lens、Monad 和学习状态的职责

建议沿用三个现有概念，避免另造一套 agent 调度：

- Lens 表达当前如何选择上下文、采用哪些教学策略和能力，并可实现改变实际流程的 loop 代码策略。
- Monad 是实际工作的 agent 实例，持有独立 history、预算、身份和协作状态，使用统一 AgentLoop 执行底座及本轮选定的 Lens 策略。
- 课程、章节、教材和学习观察由学习数据库保存，不随 Lens 文件一起复制或分享。

Bighead 的 Lens 已有只读事实投影、来源回执、绑定、候选及版本检查；其 stage 不执行任意脚本。可以借鉴这些机制，但“教学提示 + 能力绑定”的 Smallhead 包形态范围更广，不应声称已经兼容 Bighead Lens 格式。

学习方法可以被编写和修改；逐字引用核对、记忆依据的来源、数据库隔离和真实工具结果由宿主落实，不能因换一个 Lens 而失效。

## 最小包形态（建议）

```text
lenses/learning/
  lens.toml       标识、版本、用途、上下文选择、已有能力引用
  teaching.md     可编辑教学策略
  loop.mjs        可选的逐步运行策略
  examples/      代表性输入与预期行为
```

第一版应同时验证配置、Markdown、已有能力引用和最小代码运行策略。现有 Rust 学习工具可保留确定性实现；JS 经宿主接口改变运行环节，不必重写教材数据库。写一个工具名不会让工具自动可用；MCP 只是外部工具入口，不能替代 loop 策略接口。

不把教材、个人记忆、数据库、API 凭据打包进可交换的 Lens。能力描述与本机数据位置分开绑定，同一 Lens 才能用于不同课程和用户。

## 组合与生效

首个组合可以是“学习伙伴 + 当前教材范围 + 个人解释偏好”。这不应只把三段 Markdown 原样拼起来：

1. 保留基础运行约束，合并适用的教学策略；互斥策略明确显示冲突，不暗中用文件顺序决定。
2. 按本轮问题从课程、资料及学习观察中选择内容；重复证据去重，保留来源和独立预算。
3. 能力引用由宿主解析，权限不因叠加扩大；子 Monad 仍只能取得宿主给它的工具。
4. 每次运行记录实际 Lens 版本、组合顺序和上下文来源，便于复现与比较。

第一版以每个用户回合的配置快照运行。文件修改或批准新候选后，下一个回合生效；当前回合继续用旧快照。用户运行中给出的普通补充仍由 steering 处理，不需要先编辑 Lens。进一步的安全边界热切换留待后续，不能重写已经执行的工具或把旧结果改成新版本结果。

## A2A 提案与用户接受

建议把候选提交做成确定性宿主接口，与普通 A2A 自然语言任务分开：

```text
外部 agent 编写候选
  → 提交完整候选内容、基线版本和修改原因
  → 宿主校验格式并生成候选 id 与内容摘要
  → TUI 展示用途、差异、能力及数据范围
  → 用户采用、拒绝或评论修改
  → 对应候选版本发布并在下一回合启用
```

这些均为待开发接口，不是当前存在的 URL 或命令。可以借用现有 F9 审阅的交互形式，但 Lens 发布与版本保存需要真正的宿主实现，不能只靠“方案已批准”的提示词。

采用绑定候选 id、修订和内容摘要；候选被改过后，旧采用决定不覆盖新正文。一个 Lens 更新失败保留原启用版本，并允许回退。返回候选“已收到”不能答复“已接入”。

当前 A2A 的 from 是调用者自报，不是经过认证的用户身份；can_mutate/can_execute 也不能由发送者填 true 就作为授权。新增候选接口只接受候选内容，不顺带开放任意文件修改或执行。用户本机发起的明确编写与启用要求则按已有授权处理，不增加重复确认。

## 学习工具接入时必须保留的两个机制

### 真实输入与学习记忆

当前 Domain.begin_turn 从宿主取得真实用户输入；learning_memory.save 检查 evidence_quote 确实出现在其中。

迁到 TUI 后，初始输入和运行中补充都应携带宿主来源记录。A2A 来信、Lens 教学策略、教材文字及子 Monad 报告不能冒充用户自述。子研究默认只读学习材料，不直接写个人观察；需要记录时由持有真实输入依据的主任务完成。

### 引用回执与展示

cite_passage 核对“这句话是否在该片段中”，不能证明它能支持整个结论。核对结果、章节与出处通过工具结果和 TUI 展示事件传递；不要在库内打印到终端。网页片段、模型解释和已核对原文保持可区分，缺少某本书时照实说明。

## 推荐实施顺序

1. 先提取默认 loop 策略及真实阶段接口，再做通用 Lens 的包加载、校验、注册作用域、生命周期与版本快照；以最小演示 Lens 验证条件继续和装卸，不先硬编码学习入口。
2. 在 Learning Agent 仓库把领域工具提取为可复用 library 或 worker，保留 CLI 为薄宿主；Smallhead core 不依赖学习业务。
3. 第一份 Learning Lens 通过通用接口贡献已有六个工具、上下文和引用展示，处理课程绑定、真实输入来源及现有数据库复用。
4. 增加 A2A 候选收件、具体差异审阅、采用与回退。普通 A2A 对话与 TUI 使用同一运行装配规则，避免继续维护两份工具清单。
5. 再试教学 Lens 的比较与迭代：记录实际失败，候选与旧版在同一场景下对比。结构检查通过和用户喜欢不等于学习效果提高。

这些是模块边界和推荐顺序，不代表需要另开一个常驻学习服务。后续若选择 MCP 托管学习工具，也仍需解决真实用户输入绑定、引用事件及数据库写入的一致性。

## 首批验收场景

| 场景 | 检查内容 |
| --- | --- |
| 继续第四章，临时追问一个概念 | 自然聊天中定位课程，可回到章节，不强制固定阶段 |
| 对照三本书，但只导入了一本 | 提供实际读到的原文与出处，明确其余材料不足 |
| 运行中说“换成音乐的例子” | 补充进入当前任务，不丢已有输出，不重放记忆写入 |
| 另一 agent 提交“少解释、先预测”的 Lens | 可读差异；采用后下一回合实际使用对应版本 |
| 提交后修改候选正文 | 旧采用决定不能启用新正文，原版本仍可继续使用 |
| A2A 假称用户有某个学习困难 | 不能把该文字作为本轮用户证据写入个人学习记忆 |
| 恢复与回退 | 数据库和会话仍可读，实际 Lens 版本与来源可查 |

第一阶段以使用体验、真实证据和可追踪修改为目标；自动复习、掌握评估、自动候选采用及 agent 自改代码仍需独立实现与验证。
